# 经典合集与重开确认实施记录

## 需求与实现

- 重开先弹框确认，避免误触；取消与 Esc 保留局面和撤销数，确认后重置本局并恢复三次撤销。正式入口和四关试玩使用相同规则。
- 用户选择经典关全部开放。首批加入 100 张经过完整求解和路线回放的 Microban 原图；随后按用户要求补齐全部 155 张，保留编号、作者、原始尺寸和附注。
- 原图包含长条、竖向和凹凸地形，完整合集最大 30×17、最多 16 箱。外侧排版空白显示为空背景且不可行走；画布按真实宽高排版，宽图在棋盘内部滚动，移动时保持角色可见。
- 经典使用独立本地存档，记录完成图、选中图和是否在经典模式；冒险编号与数据格式保持原样。无需新服务或账号。

## 影响分析

修改正式及试玩入口的重开事件、选关弹框、棋盘比例和相关样式；增加经典发布数据、存档模块、文本导入脚本及解法证据。不修改 36 个冒险谜题与无尽生成规则。三行经典窄廊要求关卡导入校验接受最小三格尺寸。

## 风险分析

- 大图需要滚动，不能要求所有经典图在手机首屏全图显示。内部横向滚动保留格子尺寸，避免页面整体横向溢出。
- 多箱与大地图会增大计算成本。完整合集不再按箱数或求解预算过滤，141 关有完整合法解法，14 关仅完成原图与数据校验；不能将超预算视为无解。提示继续在后台执行，并增加六秒耗时预算。
- 经典集合具有明确署名分发条件，保留作者、编号和来源附注；完整收录 Microban 第一套，不声称收录作者的全部集合，也不是本项目原创谜题。
- 两种模式编号会重复，必须按模式写不同存档键，不能用经典过关误解锁冒险编号。

## 验证与测试建议

自动验证重开取消／确认、弹框时移动禁用、独立存档恢复、经典全部开放、合集下一张选择、宽图角色可见、外侧空白导入和全部经典路线回放。浏览器检查桌面、390×844 与 320×568 下的确认框、长方形画布、棋盘滚动、经典过关、刷新和冒险进度保留。

命令：`npm test`、`npm run validate:classics`、`npm run build`。冒险地图与无尽算法未修改，现有全套测试同时复核其接口与策略要求。

独立审核发现并修复两项尺寸问题：窗口缩窄未保持角色可见，以及 Phaser 切关沿用旧父容器尺寸。两项都先用失败回归复现；后者还使用真实 Phaser 缩放方法验证大图、小图与切回冒险的画布大小。

棋盘保留浏览器原生触摸与滚轮滚动，避免 Phaser 默认捕获阻止宽图拖动。使用真实 Phaser 触摸管理器和原生可取消事件验证，修复前滑动被阻止，修复后不再调用阻止默认行为。
