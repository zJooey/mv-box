# 箱子探险队

中文单人推箱子网页游戏，采用复古街机主题、暗色地板、带亮边的砖墙、橙色箱子和青色目标。使用 Phaser 4.2.1、JavaScript 和 Vite 6，无需账号或服务端。

## 启动与发布

需要 Node.js 18.20 或更高版本。

```powershell
npm install
npm run dev
npm run build
npm run preview
```

开发时打开终端显示的地址；部署时把 `dist/` 放到静态托管服务。运行时不访问关卡来源网站。

## 操作

- 把所有箱子推到青色目标，箱子只能推、不能拉。
- 电脑用方向键或 WASD。手机方向键宽 56～64 像素、高 50～56 像素；390×844 首屏包含完整方向键和常用按钮，较短屏幕允许纵向滚动。
- **每局最多撤销 3 次**有效移动，步行和推动均计一次。没有历史时不扣额度；额度不随撤销回退，用完后按钮禁用。重开、选关或刷新开始新局，恢复 3 次。
- 点击“重开”先弹出确认框，默认焦点在“取消”。取消或按 Esc 保留局面和撤销次数；点击“确认重开”才重置。过关后的“再玩一次”直接开始新局。
- 提示从当前局面求解。确实无解时建议撤销或重开，计算预算用尽时说明尚未算完；计算期间可以移动，过期结果不会显示到新局面。
- 正式 36 关依次解锁，完成后进入无尽探险。浏览器保存解锁编号和已选关卡；本次谜题更新保留已有编号，不改变存档格式。

## 经典合集

打开“关卡地图”，切到“经典合集”，即可自由选择 **Microban 完整的 155 张经典原图**，全部开放。按 David W. Skinner 原集合顺序排列，编号连续为 1～155，与页面署名中的原编号一致。箱数为 1～16，既有入门图，也有窄口调度、回程、长廊等机关。手机选关弹框为四列，只需向下滚动，不用横向滑动找右侧按钮。

经典地图保留原始墙、目标与起点，不再限制为 10×10 或正方形：包括 5×3 窄廊、19×6 长条图、8×12 竖图和 30×17 大图。地图外的排版空白不可行走，也不画成墙；室内空白仍是地板，凹凸边界保持原形。画布按实际宽高等比显示；宽图保证每格约 26 像素以上，在棋盘区域横向拖动查看，载入、移动与撤销时自动保持角色可见。大图在手机上允许纵向滚动。

经典完成记录、选中地图与当前模式使用独立的 `sokoban-classic-progress` 键。刷新恢复选中的经典图，重新开始本局；切回冒险时保留原有冒险解锁编号。经典通关不解锁冒险关，两种模式都遵循每局三次撤销及重开确认。

来源、原附注与署名见[关卡来源说明](docs/level-attribution.md)。155 关均通过原图一致性与地图数据校验，其中 141 关已正常求解并合法回放至胜利，证据保存在 `data/classic-validation.json`。另 14 关在离线的 100000 局面／六秒预算内未完成求解，仍完整收录原图，`minPushes` 标为 `null`，不声称已证明无解或最少推动次数。浏览器提示同样使用局面数与六秒耗时预算，在后台计算；超时可先操作再尝试提示。

## 正式策略关

用户认可第 3、12、24、36 关试玩后，四关原样接入正式数据，其余关卡采用人工精选的机关布局。前两关入门，此后逐步增加箱子数量。地图最大 10×10，允许长方形，墙体随机关安排，不按固定墙数填充。

| 关卡 | 箱子 | 最少推动范围 | 解题侧重点 |
|---|---:|---:|---|
| 1～2 | 1 | 2～3 | 认识推动与绕到箱后 |
| 3～8 | 2 | 6～18 | 借位、交替腾出站位 |
| 9～12 | 3 | 10～13 | 转向中转与回程借道 |
| 13～18 | 3 | 15～39 | 隔墙交换、窄口调度 |
| 19～24 | 4 | 23～41 | 多次回运、目标堵路与归位时机 |
| 25～30 | 5 | 22～68 | 侧袋、回环与共用回程 |
| 31～36 | 6 | 25～68 | 两室交错运输、六箱换位 |

推动次数与难度并非同一指标，不强制每关推数上升。第 29 关的五箱回程机关在第 35 关加入第六箱和上部目标，是一次具有新约束的复访；36 关包含 35 种墙体布局。

- 第 3 关起，完整受限搜索排除“一个箱子归位封存，再操作下一个”的解法。
- 第 9 关起，排除箱子与目标最优匹配的单箱反向推距总和始终不增加的解法，必须至少一次先退后进。
- 第 19 关起，均保留真实目标上的错误归位证据：末推前仍可解，末推上目标后无解。
- 每个箱子都参与解题，包括初始已在目标上的箱子。第 24 关另证明每箱只接手两个操作阶段仍无解；第 36 关没有这项全局证明，不能把预算耗尽作为无解证据。

第 1～3、12 关为本项目原创，其余关卡来自或改编自 **David W. Skinner**。作者、集合、原编号及改编方式保留在页面署名与[关卡来源说明](docs/level-attribution.md)，不把经典布局标为原创。作者允许这些集合在保留正确署名的条件下分发，见[作者发布页存档](https://www.onlinespiele-sammlung.de/sokoban/sokobangames/skinner/)。

## 无尽探险

无尽关使用五种六箱机关配置，包含四种墙体结构和两个不同的上仓目标配置。按编号轮换模板与朝向，在已验证起点上按固定种子反向拉箱，再检查最少推动、箱子参与和交替操作需求。再次遇到同一机关与朝向时交替使用不同起点组，减少重复。相同编号始终生成相同关卡。

筛选要求至少 25 次推动，验证路线中每箱至少接手两个阶段、至少三箱接手三个阶段；逐箱归位和推距不增加两种受限搜索必须完整无解。随机起点超出预算时放弃该候选，预算内没有选出新起点时使用同来源已完整验证的备用起点。生成和提示均在后台线程中运行。

模板、朝向及可用起点是有限的，较远编号可能再次遇到熟悉的机关；不承诺所有未来编号的谜题永不重复。第 37～100 关通过连续验关检查实际起点不重复。自动变体的趣味性仍需结合实际游玩判断。

## 验证与关卡维护

```powershell
npm test
npm run validate:levels
npm run validate:strategy
npm run validate:classics
npm run build
```

测试覆盖移动、推动、胜利、撤销额度、存档恢复、启动与提示竞态、固定策略关、无解与预算区分、生成确定性。`validate:levels` 完整复核 36 关和第 37～100 关，写入 `data/level-validation.json`，包括解法、策略结论和耗时。求解按最少推动次数搜索，路线步数不是最少步行次数证明。

- `data/curated-levels.json`：人工精选发布记录，与随机候选分开。
- `data/curated-endless.json`：署名机关模板和已验证备用起点。
- `src/levels.json`、`src/level-notes.json`、`src/endless-templates.json`：随静态游戏发布的数据。
- `src/classic-levels.json`：155 张经典发布原图；`data/microban.txt` 保留作者原始文本与附注。
- `npm run import:classics`：离线完整导入并验关，逐步回放已有解法，求解新增图；超预算不再过滤地图。成功后更新经典发布数据及证据，不更新冒险关；只有维护合集时才执行。
- `npm run generate:levels`：生成正式关的八种朝向样本，仅写 `data/level-candidates.json`，不覆盖发布数据。
- `node scripts/select-levels.js`：仅在修改人工精选记录后明确执行，从精选记录同步发布数据，再完整验关。
- `/strategy-preview.html`：开发环境的四关独立试玩，保留已认可样例，不读写正式进度，不进入默认生产包。

测试建议：桌面及 390×844、375×667、320×568 检查选关、移动、三次撤销耗尽、重开取消／Esc／确认、当前局面提示、错误归位后提示、过关、刷新恢复及第 36 关后的新关生成。经典重点检查选关中 1～155 编号连续、四列无横向溢出且可滚动到末行；第 1、6、8、44、63、144、154、155 号地图的凹边、长宽比例、棋盘滚动、大箱数提示预算、154 过关进入 155、最后一张过关返回合集，以及切回冒险后的原进度。短屏重点检查滚动与按钮遮挡。已有经典选中编号与完成记录不迁移、不清空。

## 影响与边界

本轮更新正式谜题、无尽模板、署名、验关记录和入口操作边界，保留三章结构、存档格式、静态部署方式与 3 次撤销。复杂六箱局面的提示可能达到预算，界面明确说明尚未算完；本地存储被清除后无法恢复进度。项目不包含排行榜、账号或付费功能。

经典与重开优化的影响集中在选关、独立经典存档、画布比例及确认弹框。冒险地图和无尽生成规则沿用当前版本，没有新增服务接口。大型原图需要滚动查看，未承诺每张经典图在手机首屏完整显示；提示依然有计算预算。
